05 / SECURITY PROCEDURE

How Sentinel checks a wallet

Every result follows the same read-only checks. No private keys, approvals, or transactions are requested.

01
Verify the account

Check whether the NEAR account exists and read its on-chain account state.

SOURCE · NEAR RPC
02
Collect wallet activity

Retrieve indexed native transactions, receipts, and fungible-token transfers, including available pages.

SOURCE · NEARBLOCKS EXPLORER DATA
03
Validate the evidence

Check transaction identifiers, signer, status, and timestamps before counting activity. Missing or unavailable data is marked incomplete.

CHECK · DATA COMPLETENESS
04
Apply fixed risk rules

Compare against verified threat records and review unusual transaction patterns. Community reports alone cannot trigger a block.

CHECK · DETERMINISTIC RULES
05
Return a clear verdict

Show the decision, risk score where valid, activity totals, and the evidence behind the result.

OUTPUT · AUDITABLE RESULT
BLOCKOnly a verified threat match.
WARNSuspicious patterns or signals need review.
INCOMPLETEEvidence is missing. Never treated as safe.
ALLOWChecks completed with no verified threat match. Not a guarantee.

A missing contract code is normal for a standard wallet. A code hash is an identifier, not proof of malicious code. Sentinel is a read-only risk signal, not a security guarantee.
