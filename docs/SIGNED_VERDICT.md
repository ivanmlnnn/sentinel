# Signed Sentinel Verdicts

## Purpose

The isolated signer does not authorize a payment from an unsigned JSON assessment. The Main Worker signs each internal preflight assessment with Ed25519; the Signer Worker verifies the signature and exact payment intent before it can reserve spend or submit a contract call.

## Signed payload

The canonical, deterministic payload contains:
- `sender_account`: the dedicated Testnet runtime signer account;
- `receiver_account`: the exact intended recipient;
- `amount_micro`: the exact amount in microNEAR (six decimal places);
- `nonce`: a fresh request nonce generated by the signer;
- `issued_at` and `expires_at`: Unix seconds, with a 60-second default lifetime and a 120-second maximum accepted lifetime;
- `decision`, `risk_score`, `assessment_status`, and `assessment_id`.

The signature algorithm is Ed25519. The private key is held only by the Main Worker as the `SENTINEL_VERDICT_PRIVATE_KEY` secret (base64-encoded PKCS#8). The Signer Worker receives only `SENTINEL_VERDICT_PUBLIC_KEY` (base64-encoded raw 32-byte public key). Never commit either key.

## Verification order

1. Signer creates a fresh verdict nonce and sends sender, receiver, and amount to the authenticated internal preflight endpoint.
2. Main Worker runs the trusted investigation and signs the exact returned decision and score together with the requested sender, receiver, amount, nonce, and expiry.
3. Signer verifies the Ed25519 signature, expiry, maximum lifetime, and exact sender/receiver/amount/nonce equality.
4. Only then does the signer evaluate the deterministic payment policy, claim the human approval, reserve spend, and invoke the restricted FunctionCall key.
5. Any missing key, malformed payload, stale signature, substituted field, or invalid signature fails closed.

The HMAC timestamp/nonce signature remains in place to authenticate and replay-protect the internal HTTP request. It is transport authentication, not a substitute for the signed verdict.

## Tests

Run:

```bash
node --test tests/signed-verdict.test.mjs
npm test
```

The focused tests generate ephemeral Ed25519 keys and verify valid signatures, expiry, payload tampering, and sender/receiver/amount/nonce substitution. They are local cryptographic regression tests. They do not prove the production Worker secrets are configured, that a live preflight request completed, or that a Testnet payment was sent.

## Required Worker secrets

Main Worker:
- `SENTINEL_VERDICT_PRIVATE_KEY` — base64 PKCS#8 Ed25519 private key.

Private Signer Worker:
- `SENTINEL_VERDICT_PUBLIC_KEY` — base64 raw Ed25519 public key.

Generate a dedicated Ed25519 keypair offline using an approved local cryptographic tool. Provision the private key only to the Main Worker and the public key only to the Signer Worker. Rotate by deploying the matching public key first, then the new private key, and verify the exact deployment revision. Do not print secret values in CI logs.
